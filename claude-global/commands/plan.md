# /plan - 进入计划模式

在实施任何代码改动前，执行以下步骤：

## 第一步：理解现状

1. 阅读相关代码文件
2. 理解当前架构和设计模式
3. 识别可能受影响的区域

## 第二步：制定方案

回答以下问题：

- 需要改动哪些文件？
- 改动的顺序是什么？
- 有哪些边缘情况需要处理？
- 是否有更简单的方案？

## 第三步：确认计划

将计划写入 `PLAN.md` 或直接展示给用户，等待确认后再开始实施。

## 何时使用

- 不确定方案时
- 多文件改动时
- 不熟悉的代码库
- 架构级变更

## 何时跳过

- 单行修改
- 明确的 bug 修复
- 用户已给出详细步骤
