# /tdd - 测试驱动开发

按照 TDD 流程实现功能。

## 流程

### 1. Red - 写失败的测试

```
先写测试，描述期望行为：
- 正常路径测试
- 边界条件测试
- 错误处理测试
```

运行测试，确认失败（红色）。

### 2. Green - 最小实现

写最少的代码让测试通过：
- 不要过度设计
- 只实现测试要求的功能
- 可以用硬编码先通过

运行测试，确认通过（绿色）。

### 3. Refactor - 重构

在测试保护下重构：
- 消除重复
- 改善命名
- 优化结构

运行测试，确认仍然通过。

## 循环

重复 Red → Green → Refactor 直到功能完成。

## 提示

- 每次只关注一个测试
- 测试要小而专注
- 先写断言，再写设置代码
